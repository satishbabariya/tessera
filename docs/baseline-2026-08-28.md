- **Homebrew is non-functional on this host.** Its vendored `json` 2.21.2 gem is
  incompatible with its portable Ruby 4.0.6 (`undefined method
  'default_sort_keys_proc=' for class JSON::Ext::Generator::State`). `brew
  --version` works; `brew install` does not. CMake was therefore installed from
  the official Kitware release rather than via brew. This is a host problem, not
  a project problem, but it will need fixing before Task 2 relies on system
  OpenSSL for Linux.
- `ninja` is unavailable for the same reason; the default Makefile generator was
  used locally. CI (Task 4) uses Ninja.

## Configure

Succeeded in 11.4s. **No downloads were attempted.** This empirically confirms
the spec's dependency analysis: `REALM_NEEDS_OPENSSL` (`CMakeLists.txt:293`) is
set only for Windows, Linux, and Android, so the `static.realm.io` fetch is never
reached on Apple platforms. The vendor-CDN severing in Task 2 is therefore a
Linux/Android/Windows concern only.

## Test counts differ by build type — use the right baseline

**Debug registers 5 more tests than Release.** This is a property of the suite,
not a regression, and was verified rather than assumed: after the Task 2 and
Task 3 changes, Debug still reports exactly 1665 (the pre-change figure) while
Release reports 1660.

| Build | Tests | Checks | Time |
|---|---|---|---|
| Debug | **1665** | 116,336,682 | 28.5s |
| Release | **1660** | 100,250,051 | 12.2s |

Mechanism: tests guarded by `#ifdef REALM_DEBUG` (many in `test_group.cpp`) and
by `TEST_IF(..., _impl::SimulatedFailure::is_enabled())` (`Alloc_MapFailureRecovery`,
`Impl_SimulatedFailure_OneShot`, `Impl_SimulatedFailure_Random`) are compiled out
of Release builds.

Compare like against like. A Release run showing 1660 is correct; a *Debug* run
showing 1660 would mean five tests went missing.

Check counts vary run to run with the random seed and are not a regression signal.

## ObjectStoreTests (`realm-object-store-tests`)

Established during Task 9, after the C API deletion:

```
All tests passed (161512 assertions in 403 test cases)
Test time: 81.795s
```

Total: **403 test cases**   Assertions: 161,512   Duration: 81.8s   Exit code: 0

> **The 81.8s figure is not a reliable reference and must not be used as a
> performance baseline.** Timing for this suite is dominated by two
> environmental factors, not by the code: the number of entries in `TMPDIR`
> (a single test went from 0.006s to 243.8s on a temp directory holding 48k
> entries) and local DNS behaviour (`reports DNS error` has been observed
> between 0.011s and 680.6s, occasionally failing outright). Compare test
> *counts* and pass/fail, not duration, unless you control both. See
> `docs/findings/0a-flaky-and-slow-tests.md`.

Note the binary name: the target is `ObjectStoreTests` but its `OUTPUT_NAME` is
`realm-object-store-tests` (`test/object-store/CMakeLists.txt:108`), and on macOS
it is an `.app` bundle. The full path is
`build.debug/test/object-store/realm-object-store-tests.app/Contents/MacOS/realm-object-store-tests`.
Searching for `ObjectStoreTests` finds nothing — which is how a silently skipped
suite can look like a passing one.

## Assessment

The engine is in good health. A decade dormant, and after three include-level
repairs the entire 1665-test suite passes with 116M assertions in under 30
seconds. Nothing found at baseline argues against the Tessera direction; the
outstanding question remains the sync server (Task 6).
