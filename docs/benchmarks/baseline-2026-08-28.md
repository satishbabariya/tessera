## Why Release, not Debug

An earlier Debug run was started and deliberately abandoned. Debug timings are
dominated by assertion checking and absent optimisation — the same operation
measured 782ms in Debug against single-digit microseconds in Release. A Debug
baseline could not detect the >5% regression that spec §12 criterion 9 asks
about; it would have been false coverage. Release is the only baseline worth
comparing against.

## Comparison protocol

Re-run at each phase boundary on the **same host** and compare medians, not
averages — the `stddev` column shows several operations have long tails that
distort the mean. A regression is credible only if it exceeds 5% on the median
across repeated runs; a single sample proves nothing on a machine with other
activity.

```bash
cmake -B build.release -DCMAKE_BUILD_TYPE=Release
cmake --build build.release --target realm-benchmark-common-tasks -j$(sysctl -n hw.ncpu)
cd build.release/test/benchmark-common-tasks && ./realm-benchmark-common-tasks
```

Run it with nothing else competing for CPU. Builds and test suites running
concurrently will skew results enough to manufacture or mask a 5% change.
